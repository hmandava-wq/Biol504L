Overview of today’s lab

Today’s lab will include downloading and manipulating raw sequencing data stored in NCBI’s short read archive.

This is the first step to many downstream analyses. While not always required, it is a crucial and common step for numerous bioinformatics analyses. Unpacking SRA datasets

If you were curious and used ls to peek into those newly created folders, you would have seen a file ending in .sra. This is the packed (compressed) raw data!

We need to unpack it using the tool parallel-fastq-dump.

Below, is a walkthrough of one way to do this. It is a bit involved, but it will make it easy to link the file to the existing metadata!

You should repeat the following steps for each file

  1. Make a copy of last week’s slurm script and rename it sra_fastq_dump.sh

    cp ../Slurm_Scripts/prep_conda_env.sh ../Slurm_Scripts/sra_fastq_dump.sh

  2. Make some extra edits to this file!

  3. Now we will add the command to run parallel-fastq-dump

    parallel-fastq-dump --split-files \
     --gzip \
     --threads 8 \
     -s SRR1576457 \
     -O Dmel_Maine_21C_Rep1

    Here is a breakdown of the command:

    • --split-files: separate the file into forward and reverse reads (the data are paired-end!)
    • --gzip: these raw fastq files can be big, so we will keep them compressed
    • --threads 8: tells the HPC to multi-task on this job, splitting the job into 8 pieces to speed it up
    • -s SRR#: tells the tool which dataset we want to process
    • -O NAME: the name we want the output folder to be. It is typically nice to include the metadata and/or the SRR accession (or both)

  4. Using sbatch, submit the job!

  5. Repeat for the other datasets that have FINISHED downloading. Use squeue --m to check that the files you are trying to unpack have finished downloading!

  6. As before, it is up to you to unpack the rest of the datasets during our time in lab (or outside if that’s easier). So long as one of the sequencing runs is downloaded and unpacked, you can move on to the last section, which is trimming and the quality checking!

Trimming raw SRA datasets

If you were curious and used ls to peek into those newly created folders, you would have seen a file ending in .sra. This is the packed (compressed) raw data!

We need to unpack it using the tool parallel-fastq-dump.

Below, is a walkthrough of one way to do this. It is a bit involved, but it will make it easy to link the file to the existing metadata!

You should repeat the following steps for each file

  1. Make a copy of the sra_fastq_dump.sh slurm script and rename it fastq_trim.sh

    TipIn case you get stumped 
    cp ../Slurm_Scripts/prep_conda_env.sh ../Slurm_Scripts/sra_fastq_trim.sh

  2. You will need to edit the newly copied script, sra_fastq_trim.sh. As the prior script already was set up for multi-threading (--ntasks=8), the only change is to replace the prior command with one for our read-trimming tool, fastp.

    The command is below, followed by a breakdown of the options. The below command is written for just one file, so you will need to adjust this!

    fastp \
     -i Dmel_Maine_21C_Rep1/SRR1576457_1.fastq.gz \
     -I Dmel_Maine_21C_Rep1/SRR1576457_2.fastq.gz \
     -o Dmel_Maine_21C_Rep1.Fwd.20q.80nt.fastq.gz \
     -O Dmel_Maine_21C_Rep1.Rev.20q.80nt.fastq.gz \
     -h Dmel_Maine_21C_Rep1.html \
     -R "Dmel_Maine_21C_Rep1 Report" \
     -q 20  \
     -l 80 \
     -w 8 \
     -r

    Here is a breakdown of the command:

    • -i: PATH to your forward reads
    • -I: PATH to your reverse reads
    • -o: what to name your trimmed forward reads
    • -O: what to name your trimmed reverse reads
    • -h: what to name the output quality score html file
    • -R: the report name to add to the output quality score html file
    • -q: minimum Phred quality score to use for read trimming
    • -l: minimum read length to keep a read following trimming
    • -w: number of threads to use (this should ideally be the same as --ntasks)
    • -r: perform the per-base trimming starting on the right side of the read

  3. Using sbatch, submit the job!

  4. Repeat for the other datasets that have FINISHED unpacking with parallel-fastq-dump. Use squeue --m to check that the files you are trying to unpack have finished downloading!

Cleaning up after ourselves

By now, you will have tons of files, all sitting inside your raw_read_prep folder. We do need to make sure to clean-up after ourselves on the HPC, as we have many “intermediate” files, which take up a reasonably large amount of space.

To do our cleanup, we will be using a dangerous command, rm. What makes this command so dangerous is that it removes the files/folders permanently. This is like moving a file to your trash on your computer and tossing the trash out at the same time.

Take your time when doing this! We will remove files little bit by little bit.

  1. Running and submitting jobs to SLURM will generate a ton of “slurm.out” files. These are logs from the HPC and the tool(s) you used. Typically, you won’t need these for very long, outside of handling errors.

    We can remove all of these in one step!

    WarningRemoving slurm logs 
    rm slurm-*.out

    rm followed by a file, will remove the file. You can also use the wildcard character, *. In the example above, the way this is put in the command effectively tells the computer “remove anything that startswith slurm- and ends with .out”

  2. Make sure to remove all the files that end with .json as we do not need these!

    WarningRemoving slurm logs 
    rm *.json

  3. This step is for any sequencing runs that have been fully processed, which includes downloading, unpacking, trimming. We will start by removing each of the intermediate folders, one at a time. It is okay to do this slowly and carefully, as you don’t want to need to do the processing over again.

    Below is the command to remove just one of the folders from the initial SRR downloading

    WarningRemoving Folders 
    rm -rf SRR1576457

    You can combine this with the wildcard to remove all of the SRR folders, but you need to be very certain you have “unpacked” them!

    You can also use that command to remove any folders, but again, please be cautious!
