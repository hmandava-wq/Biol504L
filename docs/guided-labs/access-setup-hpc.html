Goals of the lab overall

The skills acquired in this lab class are crucial for bioinformatic tasks using molecular data, such as data analysis, scripting, and working in high-performance computing (HPC) environments. My hope is that you don’t just type the commands into the terminal and move on – I would like you to think about what these commands are doing and start imagining how they could be useful in analyzing your own data.

W&M’s HPC server

If you are using your own computer and want to access the HPC from off-campus, then you will need to download the W&M VPN client. See this vpn installation link for instructions. If you are connected to the W&M Wi-Fi you will not need to connect to the VPN.

Once you are conneced to the W&M VPN, or using the W&M Wi-Fi, you will need to ssh into one of the sciclone’s subclusters. SciClone is comprised of many different servers (subclusters), each with their own unique set of resources (i.e., high powered CPU’s but low RAM). For most of the lab, we will be using bora.

If using your own computer and you run into issues accessing the HPC, ask me for help if needed!

Overview of the UNIX operating system and directory structure

  1. The core structure of Unix directories follows a hierarchical tree-like organization. The root directory serves as the top-level directory, and all other directories and files are organized beneath it
  2. When you first connect to the server, you will be in your home directory by default.
  3. Keep this structure in mind when you’re navigating through directories, especially once we start up/downloading data to your personal computers.
  4. If you ever get confused where you are you can return to the home directory using cd

Connecting to bora.sciclone.wm.edu

For both PCs and Macs, I recommend using the terminal to access SciClone.

  1. Open the Terminal software

HPC Navigation

Moving around the HPC uses common UNIX commands (I will provide a link to a useful cheatsheet).

When you first log in, you are interacting the HPC’s head-node (we will talk about this in class!). Additionally, the location where you first “land” onto the HPC is not where you will work!

Before we do too much, let’s use some basic commands to see what is in our current folder, move around, and check where we are:

  1. It may be kind of weird to think like this, but the parts of your laptop that you interact with really are just graphical representations of folders (directories). This is no different on the HPC! We can see the contents of this directory really easily.

    ls

  2. You should see a couple big directories, including scr10, scr20, scr30. These are the “scratch” spaces, which is our playground!

    CautionStorage Limitations

    Do not store files outside of scr10 for this lab. Additionally, do not use scr10 as a semi-permanent storage space! It is purged every few months, so please treat it like a shared kitchen and make sure we clean up after ourselves when we can!

  3. Let’s move into scr10, which is where we will do most of our work

    cd scr10

  4. It can be easy to get lost on the HPC! Thankfully, we have the best unix command ever: pwd

    pwd
    Notepwd is your Friend!

    The output of pwd is the PATH to your current location. Each / marks a different directory, so you can see exactly where you are.

    This is referred to as the absolute PATH, which is just like having exact GPS coordinates for where you are!

  5. If you ever get lost, and this will happen, simply using cd will bring you back to your home directory

  6. While we are here, let’s make a folder the lab too

    mkdir Biol404L

  7. Move into the new folder you made!

    TipIn case you get stumped

    Use the cd command to move into your folder!

    cd Biol404L

  8. Use ls and pwd to see what is inside this folder and where you are on the HPC!

  9. Move back to your home directory

    TipIn case you get stumped

    Use the cd by itself to move to your home directory!

    cd

  10. Soon we will be done moving around for a little bit, just a few more to do! Let’s move directly into our Biol404L directory, then use pwd to check!

    cd scr10/Biol404L
pwd

    You made it!

  11. We can also move “backwards” to a less “nested” folder. We can use .. to navigate back a directory relative to where we are. Let’s try it out and see what it looks like!

    cd ..
pwd

  12. Move back into your Biol404L folder (see the prior commands/steps if you need help, before asking me or a neighbor)

  13. Let’s move “backwards” two times at once!

    cd ../..
    NoteDid you notice?

    To move back one directory, we use ... However, to move back two directories, we have to put a ‘/’ in the middle!

    You can do this as many times as needed, although it can get confusing…

  14. Where are you now? How would you check?

  15. If you feel comfortable, make sure to move back into the Biol404L folder.

  16. One last task before we continue! Make a new directory called Slurm_Scripts then move into it!

    TipIn case you get stumped

    You can use the mkdir command!

    mkdir Slurm_Scripts
cd Slurm_Scripts

Great! You are now on your way to becoming a UNIX navigation expert.

This next section will combine a fair bit of commands, which will become more familiar as you work in this lab. You are not expected to be an expert right away!

Loading Modules (Software)

The HPC has quite a lot of software already installed on it. This varies by with subclusters you are working with (remember we are working on bora).

NoteWant to see the available software

If you do, then run the following command:

module avail

We do want to use containers in this lab. To do so, we will be using Anaconda and BioConda.

  1. Load the miniforge module

    module load miniforge3/24.9.2-0

  2. Let’s see what modules are loaded already

    module avail
    NoteWhat do you see?

    You should notice that two pieces of software are highlighted!

    SLURM and Miniforge3!

  3. Miniforge3 is our Anaconda software. However, it does not natively connect or know where to find bioinformatic packages. Most of those are available through BioConda.

  4. We will follow the BioConda setup instructions for Conda that are found on their website.

    conda config --add channels bioconda
conda config --add channels conda-forge
conda config --set channel_priority strict

Now we are almost ready to install software! Woohoo!

It is worth noting that conda refers to their “containers” as environments. For our purposes, this is the same thing, so do not be alarmed!

Submitting HPC Jobs

In this part we will set up a job submission script. These are important to understand as we will be using them throughout the lab course.

I have placed a template of one below (I will break down what each part means!):

#!/bin/bash
#SBATCH --job-name=some-job-name
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH -t 1:00:00
#SBATCH --mem=8G

It is nice to keep your job submission scripts together, staying organized is KEY!

Making our first job-submission-script

We will actually be submitting a job to make our container and install some software! The easiest option is to use an existing text editor in the terminal, pico

  1. Open a new file, prep_conda_env.sh, with pico Your screen should be empty!

  2. Copy and paste the template for our job submission that was found in the last section

  3. To “write” the file quickly (equivalent of saving), press ctl+o keys at the same time and hit enter

  4. Now, using your arrow keys, please replace some-job-name with env-prep and “write” the file again

  5. Great, we are ready to add our command! We will create a new environment, called sra_prep. In it we will install several pieces of software:

    • sra-tools: this makes it easy to download raw data from NCBI’s SRA repository
    • ncbi-datasets-cli: makes it easy to access genomes from NCBI’s GenBank and RefSeq
    • parallel-fastq-dump: speeds up the initial unpacking of SRA data
    • fastp: quality trimming tool (also provides lovely QC outputs!)

    Add the following to your script:

    conda create -n sra_prep ncbi-datasets-cli sra-tools parallel-fastq-dump fastp -y

    Make sure to save!

  6. Check your script (below)

    TipWorking Submission Script 
    #!/bin/bash
#SBATCH --job-name=some-job-name
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH -t 1:00:00
#SBATCH --mem=8G

conda create -n sra_prep ncbi-datasets-cli sra-tools fastp parallel-fastq-dump -y

  7. Exit the pico editor with ctl+x

  8. Submitting the job to run is incredibly easy! You will just use sbatch

    sbatch prep_conda_env.sh

  9. Now we wait… You can track the progress in the queue!

    squeue --m

    Above will show only your jobs, whereas the code below will show *all the jobs

    squeue

  10. Once this is finished, you will need to make one more container! Updating the prep_conda_env.sh script, you will need to:

Make sure this is run before we meet next!

  1. Once your job is finished, activate your container!

    conda activate sra_prep

    If it works, you will see (sra_prep) on the left-hand side of the terminal!

  2. Look at the fastp help message and all its options (so many)

    fastp -h

    Using -h with most tools will bring up usage information along with all their options. It is a lazy nice way to make to sure that the software is installed!

  3. To exit the HPC, simply press ctl+d at the same time! You should see something like: Connection to bora.sciclone.wm.edu closed.

Disconnecting from the HPC is safe to do any time that a job is running or queued!

In fact, that is the advantage of the HPC! You can queue some work then do something else (nap, eat some cookies, compose a bioinformatics sonnet, etc)

You made it! Huzzah!
